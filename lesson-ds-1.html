Read & play

Cells, the play button, and reports

You are about to write real code, and you will not install anything. The tool is Google Colab — a notebook that runs in your browser. A notebook is a page made of cells. A cell holds either text or code. Code cells have a play button on the left edge. Press it, and the code runs on a Google computer far away; the result appears under the cell about a second later.

That distance matters. The code does not run on your laptop, your school Chromebook, or your phone. It runs in a data center, and only the result travels back. Which means:

Nothing you do can break your computer. Experiment freely. The worst case is an error message, and error messages are the next thing to learn.

Errors are reports, not judgments. Red text is the computer telling you exactly what stopped it, usually with the line number and often with a guess at the fix. People who read the report go fast; people who panic at red text go slow. That is the single biggest difference between beginners who thrive and beginners who quit.

Cells run in the order you run them, not the order they sit on the page. If a notebook starts acting haunted — cells disagreeing with each other — Runtime → Restart and run all reruns everything top to bottom. Fixes it almost every time.

Two more ideas and you are ready for the notebook. First, a variable is a name for a value: city = "Tirana" stores the word, and from then on city means that word. Second, Python treats text and numbers differently: "7" in quotes is text, 7 without quotes is a number you can do math on. Half of all beginner errors are those two getting mixed up — so when you see one this week, you will know you are on schedule.

How to work in a notebook — the habit that compounds

Before more mechanics, the working method. The single habit that separates people who learn programming fast from people who stall is predict → run → compare. Before you press play on any cell — yours or the notebook's — say out loud what you expect to happen. Then run it. Then compare. When the output matches your prediction, you have confirmed a piece of your mental model. When it doesn't, you have found the most valuable thing in the room: a place where your model of the machine is wrong, small enough to fix in one minute. Students who skip the prediction step run twice as many cells and learn half as much, because nothing surprising can ever reach them — they had no expectation to violate.

The same discipline applies to errors, as a protocol. When red text appears: read the last line first (it names the kind of problem and usually the fix), then the line number (where it happened), then fix exactly one thing and rerun. Never change three things at once — if the error goes away you will not know which change mattered, and next week you will meet it again as a stranger.

And keep tiny experiments cheap. A notebook cell costs nothing to add and nothing to delete. Wondering whether "7" + 7 works? Don't wonder — open a scratch cell and ask the machine. It answers in one second and it never judges. Professional programmers do this dozens of times a day; the notebook makes the experiment loop shorter than the doubt.

Variables — the notebook's memory

A variable is a name with a value stored under it. Three rules govern all of them, and all three fit in one small program:

x = 4
x = x + 3
emri = "Ana"
print(emri, x)

Rule 1: = means store, not equals. x = x + 3 is not an equation (it would be a false one) — it is an order: take what x holds, add 3, store the result back under the name x.

Rule 2: the last store wins. A variable holds exactly one value — whatever was stored most recently, in the order the cells actually ran.

Rule 3: quotes decide whether a word is a name or text. print(emri) looks up the name and shows Ana; print("emri") shows the word emri, because quotes mean "this is the text itself."

Two more things about names. First, a copy is a copy of the value, not a connection: after a = 2 and b = a, changing a later does not reach back and change b — b took a snapshot of the 2 and kept it. Second, names are yours. Python does not care whether you write city or qyteti — a good name tells the next reader (usually you, next week) what the value means. One-letter names are for scratch work; real work deserves real words, in whichever language you think in.

The invisible whiteboard — run order and state

Here is the mental model that makes "haunted" notebooks boring instead of spooky. Behind your notebook, the session machine keeps an invisible whiteboard of every variable that exists right now and what it holds. Every cell you run reads from that whiteboard and writes to it. The page order of the cells is just typography — the whiteboard only knows the order you actually pressed play. Run a cell twice and it writes twice: if the cell says x = x * 2, a second accidental run doubles x again, silently. That is not a bug in Python; it is the whiteboard doing exactly what it was told, twice.

Runtime → Restart and run all is the exorcism because it does two honest things: wipes the whiteboard clean, then replays every cell top to bottom — so the page order and the run order finally agree. When anything confuses you this month, reach for it first. Now haunt a notebook on purpose:

Number, text, and the third thing

Every expression you write lands in one of three bins: it makes a number, it makes text, or it makes an error report. The glue operator + joins two texts or adds two numbers, but refuses to mix them — str(16) converts a number into text when you need the mix, and int("16") goes the other way. Two surprises worth meeting now: division always gives a decimal (10 / 4 is 2.5, not 2), and multiplying text repeats it — "Va" * 3 is VaVaVa. Why do types exist at all? Because the machine has to know which operations make sense: dividing two numbers means something; dividing two sentences does not. Types are how Python keeps you from asking meaningless questions — and the error report is it telling you, precisely, which question went meaningless where.

By the end of this lesson you will have met the whole week-one error family: NameError (a name that doesn't exist), TypeError (an operation between types that don't mix), SyntaxError (the sentence itself is malformed — Python couldn't even start), and, in the practice set, ValueError (right type, impossible value — int("sixteen")). What programming actually is — week-one edition

Strip away the folklore and this week's programming was three moves: store a value under a name, look it up later, and read the report when the machine refuses. Everything else — the loops in your build, the tables next week, the machine learning in the other sprints — is those three moves arranged in longer chains. Nobody memorizes commands; programmers memorize the model and look up the spelling.

One standing rule for the build, and for every build this month: when you ask an AI assistant for code — and you should — you own every word you keep. Run it, read it, and change something small to prove you can steer it. Code you can't explain is a loan, not a possession, and the interest comes due at the worst time. Next week the values stop being single numbers and become tables of thousands of rows — and the three moves come with you unchanged.

Practice

Ten predictions before the notebook

Paper-and-brain work: for each exercise, commit to an answer — say it out loud or write it down — then reveal. These are exactly the moves the notebook will ask your fingers to make.

EXERCISE 1
What does 
print(3 * 7)
show?
21. Both sides are numbers, so * is arithmetic.
EXERCISE 2
What does 
print("3" + "7")
show?
37 — as text. Quotes make them text, and + glues text end to end.
EXERCISE 3
This cell fails: 
pritn("tungjatjeta")
What will the report say, roughly — and what is the fix?
NameError: name ’pritn’ is not defined — did you mean print? The fix is the spelling. The report even guesses it for you.
EXERCISE 4
What does this show? 
x = 5
x = x + 2
print(x)
7. Line 2 is an order, not an equation: take 5, add 2, store back under x.
EXERCISE 5
This cell fails: 
print("years: " + 12)
Why — and name TWO different fixes.
TypeError — text and a number cannot be glued. Fix 1: str(12). Fix 2: a comma — print("years:", 12).
EXERCISE 6
Cell A says 
print(qyteti)
and cell B says 
qyteti = "Vlorë"
You run A first, then B. What happens, and what is the one-move cure?
A fails with NameError — qyteti did not exist yet when A ran. Cells run in the order YOU run them. Cure: Runtime → Restart and run all.
EXERCISE 7
Write one line that prints your name 3 times in a row. (Hint: the * surprise from the reading.)
print("Drita " * 3)
Multiplying text repeats it. A loop works too — that is the build.
EXERCISE 8
What does this show? 
emri = "Drita"
print("emri")
emri — the word itself. The quotes in line 2 mean "this text, literally," so the variable is never looked up.
EXERCISE 9
What does 
print(10 / 4)
show?
2.5. Division always produces a decimal in Python — even 8 / 4 shows 2.0.
EXERCISE 10
This fails: 
mosha = "16"
print(mosha + 1)
Why — and the fix?
TypeError — "16" in quotes is text, and text + number refuses. Fix: int(mosha) + 1 converts the text into a number first.
EXERCISE 11
Trace it: 
a = 2
b = a
a = 5
print(b)
2. Line 2 copied the VALUE a held at that moment. Changing a later does not reach back into b — variables hold values, not connections.
EXERCISE 12
What does 
print("Ha" * 2 + "!")
show?
HaHa! Repetition first, then the glue. Operations run in order on whatever values are there.
EXERCISE 13
This fails: 
emri = Drita
Why?
NameError. No quotes, so Python treats Drita as a variable to look up — and none exists. Quotes make it text: emri = "Drita".
EXERCISE 14
Write it: x holds "left", y holds "right". Swap them, so x prints right and y prints left. (You will want a third variable.)
temp = x
x = y
y = temp
The temp holds x’s value while x is overwritten. The classic three-step swap — you will use it for years.
EXERCISE 15
What does 
print(str(2) + str(0) + str(26))
show?
2026 — as text. Each str() makes text; + glues them in order.
EXERCISE 16
What happens: 
int("sixteen")
ValueError — a fourth report type for your collection: the TYPE is right (text in), but the VALUE cannot be converted. int("16") works; int("sixteen") cannot.
EXERCISE 17
Careful: 
x = "5"
print(x * 3)
555 — as text. x is "5" in quotes, and multiplying text repeats it. If you wanted 15, you needed int(x) * 3.
EXERCISE 18
Write it: print a line of exactly 30 dashes, then your name on the NEXT line — using only one print. (Hint: "\n" inside text means new-line.)
print("-" * 30 + "\n" + "Drita")
Repetition builds the line; \n breaks it. Two prints also work — but now you know \n.
EXERCISE 19
Trace it: 
mosha = 16
mosha = mosha * 2
mosha = mosha - 16
print(mosha)
16. 16 → 32 → 16. Each line stores over the last. Trace with a finger, line by line — that is real debugging.
EXERCISE 20
This fails: 
print("result: " + 7 * 3)
Why — trace the order.
TypeError. Python computes 7 * 3 = 21 first (a number), THEN tries to glue text to 21 — and refuses. Fix: str(7 * 3).
EXERCISE 21
Predict both: 
print(7 / 2)
print(7 // 2)
3.5, then 3. Single slash always gives a decimal; the double slash is floor division — it drops the fraction. Both exist because both are useful.

Attempt each one before revealing — the struggle is the mechanism, not a malfunction. When you have worked through them all, mark the segment complete.

Build

The three-part build

Part A — scale. Make a cell that prints a sentence about your town 500 times. You have not been taught how — that is on purpose. Ask an AI assistant or search, run what you get, and make sure you understand every word before keeping it. Then change it to print the numbers 1 to 500.

Part B — the mad-lib. Three variables — emri, mosha, qyteti (name, age, town) — and one print that weaves them into a sentence. Change the values, rerun, watch the sentence follow the variables.

Part C — the error safari. Cause three DIFFERENT errors on purpose: a NameError, a TypeError, and a SyntaxError. For each, write one sentence reading the report — what stopped the code and where.

Turn-in: screenshots of all three parts (part C includes your three one-sentence readings) — the join page explains where builds land.
